# Code for "Deep learning inference of cell type-specific gene expression from H&E histopathology predicts HPV status and prognosis in head and neck cancer"

## What is here

    notebooks/                        one notebook per figure (Figure1 .. FigureS6); each sets the
                                      root, regenerates its figure from the cache, and shows it inline
    SLIDE_EX_HNSC_ThreeCohort.ipynb   the end-to-end pipeline notebook, from bulk deconvolution
                                      to model training to application in the external cohorts
    make_figures.py                   redraw every figure in one command (see below)
    scripts/                          pipeline, data preparation, and analysis scripts
    figures/paper/                    scripts that compute the cached statistics and draw every figure
    figures/paper/cache/              the cached outputs of every analysis, so that all figures can be
                                      redrawn without a GPU and without the models
    code/SLIDE_EX_code/               the model itself and the whole-slide processing code
    requirements.txt                  Python dependencies

## Setting the root directory

Every script resolves paths from the environment variable `HNSC_ROOT`, falling back to the
directory used during development. Set it to wherever this package is unpacked:

    export HNSC_ROOT=/path/to/HNSC_code

Or copy the provided template and load it, which also sets the CTransPath weights path:

    cp config.env.example config.env    # then edit the paths
    source config.env

Large files (predictions, tile features, whole-slide images, encoder weights) are not in the
repository. See `DATA.md` for the Baidu Netdisk link and where to unpack each one.

## Redrawing every figure with one command

    export HNSC_ROOT=/path/to/HNSC_code
    python make_figures.py

This runs all ten plotting steps and takes about 75 seconds on a laptop. It needs no GPU, no
trained model and no whole-slide image: every number is read from `figures/paper/cache/`, which
holds the outputs of the analyses described in the Methods, together with the small metadata and
predicted-abundance files under `run/`.

The ten steps and the figures they produce:

    fig_plot.py             Figure 2, Figure S1
    fig4_immune_plot.py     Figure 3
    fig4_clinical_plot.py   Figure 4
    fig5_gsea_main.py       Figure 5
    protein_ext_plot.py     Figure S2
    s4_abundance_plot.py    Figure S3
    prognosis_plot.py       Figure S4
    interp_flagship_plot.py Figure S5
    go_two_cohorts_plot.py  Figure S6
    fig1_icon_heatmap.py    the schematic icons used in Figure 1

The text content of all eleven regenerated PDFs matches the figures in the manuscript exactly.

One optional panel, the gene-set overlap matrix that accompanies Figure S6, also needs the
per-patient expression predictions under `run/.../results/`, which are about 4.6 GB and are not
bundled here (they are on Baidu Netdisk; see `DATA.md`). That step reports that it was skipped and
the rest continues.

## Per-figure notebooks

`notebooks/` holds one notebook per figure, from `Figure1.ipynb` to `FigureS6.ipynb`. Each one
sets `HNSC_ROOT`, regenerates its figure from the cache, and displays it inline, so the rendered
figure is visible directly on GitHub. They use the same scripts as `make_figures.py`, so the two
routes give identical figures. Figure 1 is a schematic and is shown as the published composite,
with its cell-type icons regenerated by the notebook. Figure 3 regenerates its IHC panels from
cache and shows the spatial panel from a pre-rendered example; the full per-tile overlays for all
three cohorts need the whole-slide images and the trained model.

## Reproducing the analysis from raw data

The notebook documents the full order of operations. In outline:

1. Build the bulk expression matrices (`scripts/gen_build_bulk.py`, `scripts/build_cptac_bulk.py`).
2. Prepare the single-cell reference (`scripts/convert_oropharyngeal_ref_v2.py`, `scripts/mtx_to_rds_v2.R`).
3. Deconvolve with BayesPrism (`scripts/run_bayesprism_generic.R`), then format the training labels
   (`scripts/gen_format_labels.py`) and create the cross-validation splits (`scripts/06_make_splits.py`).
4. Train (`scripts/gen_train.py`, which drives `code/SLIDE_EX_code`) and apply the trained models to
   the external cohorts (`scripts/hnsc_v2b_external.py`).
5. Run the analyses that produce the paper's results, then the plotting scripts above.

`scripts/fix_hancock_grade.py` corrects a defect in the HANCOCK pathology file, where the grading
field stores the name of the p16 column for every p16-positive patient. It must be run before any
survival model that adjusts for clinical covariates.

## Requirements

Python 3.12 with numpy, pandas, scipy, scikit-learn, statsmodels, lifelines, matplotlib, torch,
gseapy, anndata and scanpy; R 4.4 with BayesPrism 2.2.3. The slide encoder is CTransPath, whose
weights are obtained from the original authors and are not redistributed here.

## Data

TCGA-HNSC and CPTAC-HNSCC are public, HANCOCK is available from its own authors, and the
single-cell reference is public. The derived artifacts (predictions and tile features) are on
Baidu Netdisk. See `DATA.md` for every link and the exact place to put each file.
